# Summary: Clarifying a Feature Specification with Spec Kit

The `speckit-clarify` stage scans the active feature specification for high-impact ambiguity before technical planning. A fresh agent session can reduce context noise because accepted decisions live in the constitution, `.specify/feature.json`, `spec.md`, and the built-in requirements checklist—not in hidden cross-session memory. Current Clarify asks at most five focused questions per run, one at a time, offers a recommendation or short-answer format, and writes every accepted answer into the normative sections of `spec.md` as well as a dated clarification record. In the 3D-space MVP, relevant areas include height controls, projection mode, the number of objects, scale expectations, and workspace boundaries. Product-visible behavior belongs in clarification; rendering libraries, internal coordinate representations, and other implementation mechanisms belong in `plan`. After reviewing the updated spec and checklist, proceed when no unresolved question would materially change feature scope or acceptance behavior.
