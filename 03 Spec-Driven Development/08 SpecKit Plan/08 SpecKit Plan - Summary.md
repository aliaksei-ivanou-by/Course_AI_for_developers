# Summary: Creating the Technical Implementation Plan with Spec Kit

The `speckit-plan` stage turns a reviewed feature specification into a technical implementation approach. It resolves the active feature, reads `spec.md` and the project constitution, fills the technical context, evaluates constitution gates, records research decisions, and can generate `plan.md`, `research.md`, `data-model.md`, `contracts/`, and `quickstart.md`. It does not create `tasks.md`. Running Plan without guidance is reasonable only when the stack and constraints are already established; otherwise the agent may make consequential architecture choices that require explicit direction and review. Documentation tools such as Context7 can supply current version-specific references, but sources, versions, privacy, and design suitability still need verification. Before proceeding to Tasks, check the selected stack, dependency choices, constitution compliance, data model, interfaces, validation strategy, unresolved risks, and alignment with every critical requirement.
