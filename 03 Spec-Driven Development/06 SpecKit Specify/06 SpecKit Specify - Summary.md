# Summary: Creating the First Feature Specification with Spec Kit

The `speckit-specify` stage converts one coherent product increment into a durable, technology-agnostic feature contract. Starting from the reviewed project constitution, describe the target user, desired outcome, primary workflow, boundaries, failure behavior, and measurable success without selecting frameworks or code architecture. Current Spec Kit creates `specs/<number>-<short-name>/spec.md`, maintains a built-in `checklists/requirements.md`, and records the active feature in `.specify/feature.json`; it creates only one feature directory per invocation. In the 3D-space MVP example, important decisions include grid snapping at one meter per cell, constrained camera scope, cancellation behavior, invalid geometry, exact dimensions, upward-only extrusion, and protection against accidental data loss. Confirmed answers must be written into `spec.md`, not left only in chat. Run `speckit-clarify` before planning when meaningful ambiguity remains, then review the specification and checklist before deciding how to implement the feature.
