# Summary: Executing the Implementation Plan with Spec Kit

The `speckit-implement` stage reads the approved artifacts, checks requirements-quality checklists, verifies project hygiene, and executes `tasks.md` phase by phase while respecting dependencies, test-first ordering, shared-file constraints, and `[P]` markers. Scope large runs to a phase or small task range, validate each checkpoint, and mark a task `[X]` only after its work is verified. Subagents are useful only for genuinely independent work; an orchestrator must still control file ownership, integration, and repository-level testing. Model routing and fixed compaction thresholds are platform-specific strategies, not Spec Kit requirements. When implementation reports success, inspect the diff, rerun the real quality commands, exercise the specification's user scenarios, and run `speckit-converge` to detect missing work. Review repository visibility and secrets before committing or publishing, and treat each new behavior as a new specification cycle.
