# Summary: Generating an Implementation Task List with Spec Kit

The `speckit-tasks` stage reads the approved specification, technical plan, and available design artifacts, then creates `tasks.md`: a dependency-ordered implementation checklist. The current template separates Setup, blocking Foundational work, independently testable user-story phases, and final cross-cutting work. Every task needs a checkbox, sequential ID, concrete action, and exact file path; story tasks also need a `[US#]` label. `[P]` marks only work that has no dependency on unfinished tasks and does not conflict on files. Parallel subagents can accelerate such work, but they are optional and still require an orchestrator to control dependencies, file ownership, review, integration, and final validation. This execution policy usually belongs in agent instructions rather than the project constitution. Review traceability, test obligations, phase order, and real independence, run `speckit-analyze`, and then implement in small validated phases, marking tasks complete only after verification.
