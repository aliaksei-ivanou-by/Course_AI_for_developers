# Summary: Deriving a Spec Kit Constitution from an Existing Project

Spec Kit can be adopted in a brownfield codebase without retroactively specifying the entire application. Clone the complete repository, including required submodules, wait for the checkout to finish, record a clean commit-based baseline, and initialize Spec Kit from the repository root with `specify init --here --force --integration <key>`. Review all initialization changes before asking the coding agent to draft `.specify/memory/constitution.md`. The draft must be grounded in evidence such as the README, build files, architecture decisions, public interfaces, tests, CI, history, and licenses. In the Orbiter example, physical realism, numerical accuracy, SDK stability, pluggable architecture, verification, build reproducibility, and licensing boundaries are useful candidate principles—but they are not official project policy until repository evidence and maintainers confirm them. Classify each rule as evidenced, proposed, conflicting, or unknown, then begin with one bounded feature rather than attempting to document the entire existing system.
