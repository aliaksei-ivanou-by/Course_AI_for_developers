# Advanced Techniques: What Comes Next

## The Foundation Is Complete

Thank you for completing the foundational part of the course. The preceding modules introduced the core practices needed for disciplined AI-assisted development: structured prompting, specification-driven work, context engineering, reusable agent capabilities, subagents, and framework selection.

The remaining modules are optional. They extend the foundation with more advanced techniques, experiments, and practical showcases rather than replacing the workflows already covered.

## An Evolving Module

Advanced AI-development practices change quickly, so this module will grow as useful new material becomes available. Its content is intentionally not presented as a fixed or final syllabus.

Return to the course periodically to check for new lessons, or subscribe to the course newsletter if you want to receive update announcements.

## Planned Directions

Future lessons will focus on three broad areas:

### Open-Source Models

You will explore where open-source models fit into development workflows and how to evaluate them for real tasks. Model choice should consider capability, hardware requirements, latency, cost, privacy, licensing, and operational maintenance rather than benchmark scores alone.

### Open-Source Agent Harnesses

A harness is the software layer around a model that manages instructions, context, tools, permissions, execution, and feedback. Working with open-source harnesses provides more control over this layer, but also makes the developer responsible for configuration, security, upgrades, and reliability.

### Mastering Your Own Process

The ultimate goal is not to copy one tool setup. It is to develop a repeatable process that fits your projects and team. This includes deciding how work is specified, how context is supplied, when agents or frameworks are useful, how results are verified, and which decisions must remain under human control.

## How to Approach the Advanced Material

- Select lessons that match a real engineering need instead of adopting every new tool.
- Verify current documentation because model capabilities, integrations, and interfaces change frequently.
- Evaluate tools with representative tasks and compare correctness, effort, latency, cost, privacy, and maintainability.
- Keep generated code and automated actions subject to the same review, testing, security, and compliance standards as other engineering work.
- Preserve the foundational practices from earlier modules even when experimenting with a different model or harness.

## Key Takeaway

The core course is complete, while the advanced section will continue to evolve. Use it as a practical laboratory for open-source models, agent harnesses, and a development process tailored to your own constraints—not as a requirement to replace a workflow that already works well.
