# Summary: Context Windows, Prompt Caching, Cost, and Performance

The context window is the model's per-request working set, while session usage and billable cost accumulate under separate accounting rules. Prompt caching reuses computation for a stable request prefix: cache-write tokens create an entry, and cache-read tokens reuse it at a lower input rate. Cached tokens still occupy the context window and remain visible to the model, so caching does not replace pruning or compaction. Keep the active context sufficient and relevant by loading focused evidence, persisting durable state in project files, compacting a continuing objective, and starting a new session when the objective changes. Interpret local cost estimates only after confirming the model, provider, authentication mode, cache categories, output usage, and separately priced tools. Optimize the cost and quality of the completed task rather than minimizing the token count of one prompt.
