# Summary: One Task, One Chat

Use one agent session for one coherent objective with one definition of done. Investigation, planning, implementation, tests, and required documentation can remain together when they serve that outcome; an unrelated feature, repository, review, or business goal should normally start a new session. This prevents context clash from conflicting instructions and context distraction from irrelevant history. Compact when continuing the same task, fork when comparing divergent approaches, and begin a clean session when the objective changes. New sessions still need a concise task contract containing the outcome, relevant evidence, constraints, completion criteria, and decision boundaries. For parallel coding work, isolate files with separate cloud environments, branches, or worktrees as well as separate chats. Preserve requirements, decisions, progress, and validation evidence in durable project artifacts so a fresh session can recover without copying the entire conversation.
