# Summary: Introduction to AI Development Frameworks

An AI development framework is a portable package of skills, subagents, commands, templates, and workflow rules for AI-assisted development. It relates to a personal custom setup the way React or .NET relates to a product-specific library: it is designed to work for many users and projects. GitHub Spec Kit, used in the previous module, is such a framework and embedded both spec-driven and test-driven discipline into the workflow.

Frameworks proliferated in 2025 to fill gaps in agent tooling: clarifying questions, planning, structured specs, task tracking, and standards injection. In 2026, stronger models and native Claude Code features such as plan mode, the question-and-answer interface, to-do lists, subagents, skills, and session rewind cover most everyday work. Brian Casel, the creator of Agent OS, estimates that plain Claude Code handles about 90% of his work, while product judgment, scope decisions, and review remain the developer's responsibility.

Frameworks still help with greenfield product design (Design OS), legacy codebases with established standards (Agent OS), large multi-session initiatives (Taskmaster), enforced engineering discipline (Spec Kit, Superpowers), and teams that need a shared, reproducible process. Other popular options include the "Oh My" family for OpenCode, Codex, and Claude Code. Start with the plain agent, add a framework only when you feel real recurring friction, inspect what it installs, measure its context cost, and verify current project status before adoption.
