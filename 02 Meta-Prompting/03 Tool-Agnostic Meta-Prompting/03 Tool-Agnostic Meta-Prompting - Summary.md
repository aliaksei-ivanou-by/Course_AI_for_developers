# Summary: Tool-Agnostic Meta-Prompting

Meta-prompting uses one prompt to improve another while keeping prompt preparation separate from task execution. A structured template should clearly identify the meta task, the draft development request, the permitted investigation, and the expected output so that the agent does not start modifying code prematurely. When the enhancing agent can inspect the repository, it can ground the rewritten prompt in the project's actual languages, files, conventions, tests, and architecture; a general chatbot without that access can usually improve only wording and structure. In the lesson, this prevents the TypeScript assumptions made by a context-free chatbot, but the resulting Go implementation still does not fully match the intended fixed terminal status line because that UX behavior was never defined precisely. The enhanced prompt therefore remains a proposal: repository context cannot replace explicit requirements, review, or validation. This workflow is tool-agnostic and should use permissions, model settings, and validation effort appropriate to the task's complexity and risk.
