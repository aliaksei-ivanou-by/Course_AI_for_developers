# Summary: Tool-Agnostic Meta-Prompting

Meta-prompting uses one prompt to improve another while keeping prompt preparation separate from task execution. A structured template should clearly identify the meta task, the draft development request, the permitted investigation, and the expected output so that the agent does not start modifying code prematurely. When the enhancing agent can inspect the repository, it can ground the rewritten prompt in the project's actual languages, files, conventions, tests, and architecture; a general chatbot without that access can usually improve only wording and structure. The enhanced prompt remains a proposal that must be reviewed for incorrect context and assumptions before the same or another agent implements it. This workflow is tool-agnostic and should use permissions, model settings, and validation effort appropriate to the task's complexity and risk.
