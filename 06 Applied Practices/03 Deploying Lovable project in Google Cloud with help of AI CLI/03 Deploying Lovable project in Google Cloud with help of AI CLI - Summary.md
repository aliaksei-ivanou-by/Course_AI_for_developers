# Deploying a Lovable Prototype to Google Cloud with an AI CLI — Summary

A Lovable prototype can be moved into a company-controlled Google Cloud project in roughly twenty minutes: connect the project to GitHub (Lovable keeps a two-way sync with the active branch), clone it with `gh`, authenticate `gcloud`, run `/init` in an AI CLI so it understands the stack, and ask for a bounded deployment with an explicit project ID, region, and Cloud Run as the target. The agent generates a multi-stage `Dockerfile` with an Nginx configuration, builds the image with Cloud Build, stores it in Artifact Registry, and deploys a Cloud Run service that scales to zero when idle. Review every command, especially `--allow-unauthenticated`, API enablement, IAM changes, and build-time `VITE_*` variables; never place secrets in a frontend bundle. Remove Lovable branding—favicon, title, Open Graph tags, `lovable-tagger`—as a separate, committed task, remembering that pushes to the synced branch also change the Lovable project. Custom domains require a load balancer or Firebase Hosting in `europe-central2`, where Cloud Run domain mapping is unavailable. Google AI Studio offers a faster one-click Cloud Run deployment, but with less control and only for Google Cloud. The recording used Gemini CLI and Google Developer Program credits; since June 2026 Gemini CLI no longer serves consumer AI Pro/Ultra tiers and Developer Program benefits for personal accounts have changed, so verify current tools, eligibility, credits, and budgets before repeating the workflow.
