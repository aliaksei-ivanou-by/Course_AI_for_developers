# Self-Healing CI/CD with Claude Code Agent Teams — Summary

A coding agent can repair a failing pipeline without manual log copying: start a clean Claude Code session in plan mode, give it a link to the failed GitHub Actions job, and let it read the logs through the GitHub CLI (`gh run view --log-failed`), fix the cause, push to the existing pull request branch, and watch the new run until it passes. In the recorded demonstration, an agent team with Haiku reading logs, Sonnet changing code, and Opus orchestrating and reviewing fixed a broken Docker build for a Kafka deployment in one attempt and about five minutes. A CLI avoids MCP context overhead and uses the developer's existing login, so access must be scoped: the default `gh` token can push, re-run workflows, and delete unprotected branches, but cannot delete repositories or packages or push workflow-file changes without extra scopes. Protect branches, run first in a sandbox, state that the code is local, and add guardrails—fix the root cause, never disable tests or security scans, limit attempts, and keep the merge as a human decision. Agent teams are experimental and cost more tokens than a single session or a subagent, which is often enough for simple failures; the same pattern adapts to GitLab with `glab` and to on-premises Git hosts.
