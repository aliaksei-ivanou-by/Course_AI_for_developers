# Summary: RTK and Caveman

RTK and Caveman reduce different parts of an AI coding session. RTK filters supported shell-command output before it enters the model context, targeting input tokens. Caveman's response skill makes agent prose terse, targeting output tokens; its broader proxy and runtime can also compress material the agent reads.

Compression can hide diagnostics or create ambiguity, so raw data must remain recoverable and clarity must win for security warnings, irreversible actions, complex procedures, and formal handoffs. Treat hooks and proxies as sensitive development infrastructure: inspect installation changes, processing boundaries, storage, telemetry, versions, licenses, security policy, and uninstall behavior. Vendor percentages are not guaranteed session savings. Evaluate paired repository tasks, enable one component at a time, and compare provider-reported usage, task success, latency, reruns, omitted evidence, and human review time. Keep a tool only where it lowers total completed-task cost without weakening correctness or reviewability.
